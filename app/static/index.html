场景预设：
#域名（支持 .test 实验后缀）客户端查询 ID（0-65535，可写 0x 前缀）
1

每行会各自打开一个独立的 UDP 客户端套接字（独立源端口）。即使多行使用完全相同的 ID， 转发器也必须按“上游随机唯一 ID + 待处理客户端端点”分别投递，不会串答。

如何观察这些保证

  • 同 ID 并发：所有行使用相同 ID、不同域名。每个结果卡片都应显示自己域名的答案 （实验上游按域名哈希返回不同的 198.51.100.x）。
  • 错误问题包 / 错误来源包 / QR=0：上游先发一个伪造包再发正确应答；页面只应显示正确 IP， 且后续查询不会命中被污染的缓存。
  • 倒序应答：ooo-* 域名让上游把并发查询攒起来，按到达的相反顺序回复； 每个卡片仍须拿到自己的答案。
  • 无应答超时：drop-* 域名让上游不回复；约 2 秒后应看到 SERVFAIL。
  • 缓存 TTL：先用 ttl5-cache.example.test 查询一次，再点一次“并发查询”（可换 ID）。 第二次不访问上游，ID 恢复为本次客户端 ID，TTL 按已过秒数扣减；多次命中不会延长总寿命。
  • 页面调用 POST /api/query，后端为每个请求新建 UDP 套接字并发往转发器； 转发器再以随机唯一上游 ID 访问上游。
